Platform capabilities

Everything compliance teams need to reason over legal norms

From process model annotation to queryable knowledge graph — the complete pipeline for machine-readable legal compliance.

Norm Determination Engine
Automatically identifies which legal norms — obligations, permissions, prohibitions — apply to each path through your business process model.
OWL 2 Knowledge Graph
Extracts agents, legal objects, deontic norms, regulatory sources, and conditions as OWL 2 ABox individuals — ready for DL reasoning in Protégé or any OWL 2 engine.
SWRL Inference Rules
Generates Semantic Web Rule Language rules that encode when norms apply based on gateway conditions — enabling automated inference over your compliance knowledge base.
SPARQL 1.1 Endpoint
Query your legal knowledge graph directly with SPARQL. Explore norms by regulation, agent, binding force, or risk level — with built-in queries for common compliance patterns.
Compliance Check Interface
A guided Q&A experience derived from your process model. Answer the gateway conditions and instantly see which obligations or recommendations apply to your specific case.
LegalRuleML Export
Export norms in LegalRuleML-compatible structured format with full regulatory provenance — regulation, article, paragraph, binding force, and risk level metadata preserved.
How it works

From annotated process to compliance knowledge in four steps

The NORMA pipeline connects your BPMN process models directly to a machine-readable legal knowledge graph.

1
Annotate your BPMN
Use the NORMA Camunda element template to tag tasks and gateways with deontic metadata: agent, obligation type, regulation, article, binding force, and risk level.
2
Upload or paste XML
Drop your BPMN file into the workspace or paste the XML directly. The pipeline parses the graph, normalizes entities, and builds the OWL 2 ABox and SWRL rules in seconds.
3
Answer the conditions
The compliance check interface presents the gateway conditions from your model. Answer each with Yes or No to describe your specific scenario — NORMA evaluates which norms apply.
4
Query, reason, export
Use the built-in SPARQL endpoint to query your knowledge graph, load the Turtle ABox in Protégé for DL reasoning, or download the SWRL rules for integration with your own toolchain.

Get started

Annotate in Camunda.
Reason in OWL 2.

Download the NORMA element template for Camunda Modeler, annotate your BPMN processes with deontic metadata, and upload them here to build a live compliance knowledge graph.

camunda8-compliance-template.json
Camunda 8 element template · 25 annotation fields · 7 groups
Camunda Modeler 8
Required to annotate BPMN files · Free download
1
Install the element template
Download the template above and copy it into the Camunda Modeler element-templates directory for your OS, then restart Camunda Modeler.
macOS~/Library/Application Support/camunda-modeler/resources/element-templates/
Windows%APPDATA%\camunda-modeler\resources\element-templates\
Linux~/.config/camunda-modeler/resources/element-templates/
2
Annotate your BPMN process
Open or create a BPMN file in Camunda Modeler. For each task or exclusive gateway that carries a legal norm, select the element, open the Properties Panel, and choose NORMA Compliance from the template dropdown. Fill in the deontic type, agent, action, object, regulation, article, binding force, and any additional fields.
3
Upload your BPMN here
Drop your annotated .bpmn file into the workspace upload panel. The NORMA pipeline parses the process graph, extracts all deontic norms, and generates the OWL 2 ABox and SWRL rules live in your session — no CLI required.
4
Build from CLI (optional)
For batch processing or CI/CD integration, run the pipeline from the project root:
python norma_build.py regulations/eu-ai-act/
Outputs: .abox.ttl (OWL 2 ABox) and .swrl.owl (inference rules). Place generated files in a regulation pack folder; the server picks them up on startup.

Installation
1
Copy the JSON file into the Camunda Modeler element-templates directory for your OS — create the folder if it does not exist.
macOS~/Library/Application Support/camunda-modeler/resources/element-templates/
Windows%APPDATA%\camunda-modeler\resources\element-templates\
Linux~/.config/camunda-modeler/resources/element-templates/
2
Restart Camunda Modeler. The template will appear in the Properties Panel when you select a task or exclusive gateway.
3
Open your BPMN, select a task or gateway, choose NORMA Compliance from the template dropdown, and fill in the annotation fields.
4
Save the .bpmn file and upload it here — or run python norma_build.py regulations/<pack>/ from the project root to build the ABox + SWRL files offline.
